# Database Design

Migrations `V1__create_core_schema.sql`, `V2__create_security_tables.sql`, and `V3__add_room_type.sql` create the following tables:

| Table | Purpose | Important constraints/indexes |
| --- | --- | --- |
| `users` | Accounts and login lock state | unique email, lower-email index, role check |
| `refresh_tokens` | Hashed rotating refresh-token sessions | unique hash, user and expiry indexes |
| `rooms` | Owner-managed room listings | owner FK, bounded room type, status/rent/bathroom checks, owner and search indexes |
| `favorites` | User-to-room saved listings | composite primary key, user/date index |
| `rental_requests` | Applicant-to-owner room workflow | applicant/owner/room FKs, status check, pending partial unique index |
| `audit_logs` | Security and business audit trail | actor FK with null-on-delete, event/date indexes |
| `login_attempts` | Persisted authentication attempt history | user/email/status/date indexes, status check |
| `security_events` | Security event history exposed to administrators | actor/type/status/date indexes, status check |

## Relationship Model

```text
users 1----* rooms
users 1----* refresh_tokens
users *----* rooms via favorites
users 1----* rental_requests as applicant
users 1----* rental_requests as owner
rooms 1----* rental_requests
users 1----* audit_logs
```

Timestamps are UTC `timestamptz`. UUIDs are generated by the application. Hibernate is configured with `ddl-auto=validate`; schema changes must be delivered as forward-only Flyway migrations.
